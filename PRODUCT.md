# Product

## Register

product

## Users

Creadores de contenido que trabajan con vídeos largos y necesitan convertir una sola grabación en varias piezas publicables sin saltar entre herramientas. El usuario principal trabaja desde un ordenador de edición, entiende el contenido que ha grabado, pero no quiere gestionar manualmente transcripción, selección de clips, copy y publicación para cada plataforma.

## Product Purpose

Shortsmith centraliza el flujo posterior a una grabación: ingesta o referencia de un vídeo local, transcripción, análisis editorial, selección y render de clips verticales, preparación de metadata, creación de Stories y publicación mediante APIs oficiales. El éxito consiste en reducir trabajo repetitivo sin ocultar decisiones importantes: cada resultado debe poder revisarse, editarse y publicarse de forma consciente.

## Brand Personality

Profesional, directa y editorial. La interfaz debe transmitir control y criterio, con lenguaje claro en español y suficiente contexto para que el creador sepa qué está ocurriendo, qué requiere configuración y qué se publicará.

## Anti-references

- Un panel técnico que obliga a conocer nombres de variables, rutas internas o estados de API para completar una tarea cotidiana.
- Un generador de contenido genérico que inventa datos, promete viralidad o publica sin revisión explícita.
- Un dashboard de tarjetas repetidas, adornos SaaS, gradientes morados, glassmorphism o jerarquía visual débil.
- Un formulario interminable que mezcla creación, revisión, publicación e historias sin navegación ni contexto.

## Design Principles

1. Organizar el producto según el flujo real del creador: preparar, procesar, revisar y publicar.
2. Mostrar progreso y bloqueos con lenguaje útil, no con jerga interna.
3. Mantener siempre una revisión humana antes de publicar y hacer editables los textos generados.
4. Diferenciar evidencia, sugerencia editorial y estado técnico para no crear falsa confianza.
5. Mantener una experiencia local rápida y privada; las conexiones externas solo aparecen cuando una acción las necesita.

## Accessibility & Inclusion

Objetivo WCAG 2.2 AA. Navegación completa por teclado, foco visible, regiones de estado anunciables, contraste mínimo de 4.5:1 para texto normal, controles con etiquetas explícitas y reducción de movimiento según preferencias del sistema. La información de estado nunca dependerá solo del color.
